# Описание функционала приложения (app.py)

Ниже приведено подробное описание моделей, маршрутов и ключевой логики из `app.py`.

## Модели (SQLAlchemy)

1. `User`
   - `id`: Integer, PK
   - `username`: String(150), уникально, обязательное
   - `email`: String(200), уникально, обязательное
   - `password_hash`: String(200)
   - `role`: String(50) — роль: `user`, `support`, `manager`, `admin` (по умолчанию `user`)
   - `company_name`: String(255), nullable
   - `address`: String(500), nullable
   - `first_name`: String(150), nullable
   - `middle_name`: String(150), nullable
   - `last_name`: String(150), nullable
   - `phone`: String(50), nullable
   - `created_at`: DateTime, default utcnow
   - Связи:
     - `tickets_created` (Ticket.creator)
     - `tickets_assigned` (Ticket.assignee)
     - `comments` (TicketComment.author)
     - `attachments` (Attachment.uploader)

2. `Ticket`
   - `id`: Integer, PK
   - `title`: String(255), обязательное
   - `description`: Text, обязательное
   - `status`: String(50) — `open`, `in_progress`, `resolved` (по умолчанию `open`)
   - `priority`: String(20) — `low`, `medium`, `high` (ключ)
   - `creator_id`: FK -> `user.id`
   - `assignee_id`: FK -> `user.id`, nullable
   - `resolved_at`: DateTime, nullable
   - `created_at`, `updated_at`: DateTime
   - Связи:
     - `comments` (TicketComment.ticket) — cascade delete
     - `attachments` (Attachment.ticket) — cascade delete

3. `TicketComment`
   - `id`: Integer, PK
   - `ticket_id`: FK -> `ticket.id`
   - `author_id`: FK -> `user.id`
   - `content`: Text
   - `created_at`: DateTime
   - Связь: `attachment` (один к одному)

4. `Attachment`
   - `id`: Integer, PK
   - `filename`: String(300) — файл на диске
   - `original_name`: String(300)
   - `ticket_id`: FK -> `ticket.id`, nullable
   - `uploader_id`: FK -> `user.id`
   - `comment_id`: FK -> `ticket_comment.id`, nullable
   - `created_at`: DateTime


## Инициализация БД и поддержка изменений схемы

- При старте выполняется `create_tables()` и `ensure_profile_columns()` в контексте приложения.
- `create_tables()` вызывает `db.create_all()` при отсутствии таблиц, затем пытается выполнить `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` для полей профиля.
- `ensure_profile_columns()` дополнительно выполняет `ALTER TABLE` для колонок: `company_name`, `address`, `first_name`, `middle_name`, `last_name`, `phone` и для `ticket.resolved_at`.
- Примечание: эти `ALTER` выполняются в рантайме при старте — при изменениях в коде для применения к уже существующей базе нужно перезапустить веб-приложение (контейнер).


## Маршруты (Flask)

- `/` — `index` — отображение главной страницы.

- `/register` (GET, POST) — регистрация
  - Сохраняет: `username`, `email`, `password`, `first_name`, `middle_name`, `last_name`, `company_name`, `phone`, `address`.
  - Валидация уникальности `username`/`email`.

- `/login`, `/logout` — аутентификация.

- `/dashboard` — перенаправляет по роли: `admin` -> `/admin/users`, `manager` -> `/manager`, `support` -> `/support`, иначе пользовательская панель `/user`.

- Админские маршруты:
  - `/admin/users` — список пользователей (только admin).
  - `/admin/users/<id>/role` (POST) — смена роли (admin только).
  - `/admin/user/<id>/edit` (GET, POST) — редактирование профиля пользователя (админ может редактировать username/email и поля профиля).
  - `/admin/user/<id>/delete` (POST) — удаление пользователя: удаляются тикеты, комментарии, вложения создателя; снимается назначение у тикетов, где пользователь был исполнителем.
  - `/admin/user/<id>/password` (GET, POST) — смена пароля пользователю (admin).

- Менеджерские маршруты:
  - `/manager` — статистика менеджера: по создателям (ФИО), по компаниям, по исполнителям (ФИО), последние тикеты.
  - `/manager/tickets` — список всех тикетов (менеджер).
  - `/manager/ticket/<id>/edit` — редактирование тикета (статус, приоритет, исполнитель).
  - `/manager/ticket/<id>/delete` — удаление тикета (менеджер/админ).
  - `/manager/users`, `/manager/user/<id>/profile` — просмотр и редактирование профилей пользователем с ролью manager.

- Техподдержка (support):
  - `/support` — панель техподдержки:
    - Отображаются: открытые тикеты (`status='open'`), мои тикеты в работе (`status='in_progress' and assignee_id=current_user.id`), выполненные мои (`status='resolved' and assignee_id=current_user.id`).
    - Функции: взять в работу, экспорт PDF.

- Тикеты и операции с ними:
  - `/ticket/create` (GET, POST) — создание тикета с возможной загрузкой вложения.
  - `/ticket/<id>` — просмотр тикета, отображение статуса, приоритета, создателя (ФИО + компания), исполнителя (ФИО), создано/выполнено, список комментариев и вложений, форма для добавления комментария (с вложением).
  - `/ticket/<id>/export_pdf` — экспорт тикета в PDF (см. раздел PDF ниже).
  - `/ticket/<id>/take` — взять в работу (support).
  - `/ticket/<id>/resolve` — пометить выполненным (support, если исполнитель совпадает).
  - `/ticket/<id>/comment` — добавление комментария (с вложением).


## PDF-экспорт

- Реализован в `/ticket/<id>/export_pdf`.
- Используется библиотека `reportlab` (`pdfgen.canvas`, `pdfmetrics`, `TTFont`).
- При формировании PDF регистрируется первая найденная TTF из `static/fonts/`. Если шрифтов в проекте нет, пробует стандартные пути для DejaVu в системе.
- В PDF включаются:
  - Заголовок: `Тикет #id: title`.
  - Статус и приоритет (отображаемые через словари `STATUS_LABELS` и `PRIORITY_LABELS`).
  - Данные автора: `Фамилия Имя Отчество`, `Компания`, `Адрес`, `Телефон`.
  - Создано (дата/время), описание (с наивной обёрткой строк), список комментариев с автором и временем.
- PDF генерируется в памяти (`io.BytesIO`) и возвращается через `send_file`.


## Шаблоны (Jinja2)

- В проекте есть шаблоны для:
  - `base.html`, `index.html`, `register.html`, `login.html`, `profile.html`, `user_dashboard.html`, `support_dashboard.html`, `manager_dashboard.html`, `manager_tickets.html`, `manager_users.html`, `manager_performers.html`, `ticket.html`, `create_ticket.html`, `admin_users.html`, `admin_change_password.html` и др.
- Применяются фильтры шаблонов:
  - `status_label` — перевод ключа статуса в человекочитаемый русский текст.
  - `priority_label` — перевод ключа приоритета.


## Загрузка файлов

- Вложения сохраняются в `app.config['UPLOAD_FOLDER']`.
- Разрешённые расширения определены в `ALLOWED_EXTENSIONS`.
- При загрузке файлы сохраняются с префиксом метки времени и оригинальным безопасным именем (`secure_filename`).


## Безопасность и права доступа

- Изменения/просмотр ресурсов ограничены по ролям:
  - `admin` — все права на управление пользователями и ролями.
  - `manager` — редактирование/удаление тикетов, просмотр статистики и пользователей.
  - `support` — работа с тикетами (взять в работу, пометить выполненным), свои в работе/выполненные.
  - `user` — создание и просмотр собственных тикетов.
- Контролируется через `current_user.role` и декоратор `@login_required`.


## Примечания по эксплуатации

- После внесения изменений в модель/колонки (например, добавлено `middle_name`) — перезапустите веб-приложение (контейнер), чтобы `ensure_profile_columns()` выполнил `ALTER TABLE` и добавил колонки в существующую БД.
- Для отладки PDF-шрифтов проверьте логи на сообщения о регистрации шрифтов.
